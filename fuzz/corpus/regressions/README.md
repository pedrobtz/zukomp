# Regression corpus

Minimised inputs that once caused a finding. Never pruned, replayed by
`fuzz/replay.sh`, and each one has a matching testthat test — a fuzz
finding without a regression test is a finding that can come back.

| input | finding |
|---|---|
| `empty-input-null-pointer-arith` | A zero-length input buffer has a NULL pointer with a zero size, which is legal. `buf->src + buf->src_pos` on it is arithmetic on a null pointer: undefined in C, flagged by UBSan, and reachable from `komp_decompress(raw(0), "deflate-raw")`. Fixed in `codec_deflate.c` by `zu_int_cat()`/`zu_int_at()`, and by never handing miniz a NULL `next_in` — `tinfl` computes `pIn_buf_next + *pIn_buf_size` unguarded. |
| `gzip-header-only` | A gzip stream truncated to its magic plus CM. Exercises the header parser's need-more-input path at the earliest point it can be reached. |
| `lifecycle-zstd-no-forward-progress` | A `fuzz_lifecycle` input (not minimised; libFuzzer's own output from CI): an empty zstd frame decoded through a handle, then more than 16 `ZU_RUN` calls offering nothing. libzstd reports `noForwardProgress_inputEmpty` from the 16th, and zukomp read it as corrupt data (#100). Fixed in `codec_zstd.c` by treating it, and `_destFull`, as nothing having moved. Test: "any number of calls that move nothing leave the stream intact" in `test-lifecycle.R`. |
| `raw-truncated-finish-order` | A `fuzz_decode_raw` input (not minimised; libFuzzer's own output from CI): a valid body that stops short of its last block, decoding to 153319 bytes before the input runs out. When `ZU_FINISH` came with the final bytes it was refused after 131072 bytes, and when it came on a later empty call, after all 153319 (#68's FINISH-order oracle). `mz_inflate()` given `MZ_FINISH` stops tinfl the moment its input runs out, with decoded bytes still in its dictionary. Fixed in `codec_deflate.c`, which no longer hands the decoder `MZ_FINISH` on any call. Test: "a truncated DEFLATE-family stream delivers the same bytes whichever call carries ZU_FINISH" in `test-lifecycle.R`. |
| `gzip-truncated-finish-order` | The same finding through `fuzz_decode_gzip` (65536 against 78680 bytes), and the same fix and test. |
| `zlib-unused-distance-code` | A `fuzz_decode_zlib` input (not minimised): a dynamic block whose distance table is a single one-bit code, then a match written with the table's unused code. zlib refuses it ("invalid distance code"). tinfl's lookup entry for the unused code was 0, which decodes as distance 1 with no bits consumed, so zukomp delivered 2229 bytes zlib never would and failed only at the Adler-32. Fixed by `tools/patches/miniz/0006-reject-reserved-codes.patch`. Test: `raw-dist-single-unused-code` and its control `raw-dist-single-ok` in `test-malformed.R`. |
| `boundaries-zstd-empty-last-block-content-size` | A `fuzz_stream_boundaries` input (not minimised): a zstd frame that declares 4312 bytes of content and holds one empty last block. libzstd's streaming decoder skipped its content-size check after an empty last block, so the frame was refused when decoded whole and accepted, as empty, when split. Fixed by `tools/patches/zstd/0002-check-content-size-after-empty-last-block.patch`. Test: "a frame ending in an empty last block is held to its declared content size" in `test-zstd.R`. |
| `zstd-rle-block-over-maximum` | A `fuzz_decode_zstd` input: a frame with a 1 KiB window and one last RLE block declaring 1350655 bytes, above RFC 8878's Block_Maximum_Size. zukomp refused it, rightly, and so do libzstd's streaming decoder and the `zstd` CLI; the oracle's reference, libzstd's one-shot `ZSTD_decompressDCtx()`, never compares a block with `blockSizeMax` and decoded it, so the oracle reported a false refusal. Fixed in the oracle: `zu_fuzz_zstd_block_too_large()` in `fuzz_oracle.h` makes the reference apply the rule. Test: "a block larger than its frame's Block_Maximum_Size is refused" in `test-zstd.R`, which pins zukomp's side. |
| `boundaries-zstd-rle-empty-zero-window` | A `fuzz_stream_boundaries` input (not minimised): a single-segment zstd frame declaring Frame_Content_Size 0, so a Window_Size and a Block_Maximum_Size of 0, ending in an RLE block of size 0 and a wrong checksum. Decoded whole it was a checksum mismatch; split, libzstd's streaming decoder compared the RLE block's one-byte body with the maximum of 0 and called it corrupt -- and does so for the same frame with a correct checksum, which the `zstd` CLI decodes. Fixed by `tools/patches/zstd/0003-check-rle-block-size-not-body.patch`. Test: "an RLE block is measured by its regenerated size, not its body" in `test-zstd.R`. |
| `boundaries-zstd-empty-compressed-block` | A `fuzz_stream_boundaries` input (not minimised): a zstd frame ending in a *compressed* block of size 0, then a checksum. Whole, libzstd called it corrupt, as the `zstd` CLI does; split, its streaming decoder took the block for an empty raw block and reported a checksum mismatch. Fixed by `tools/patches/zstd/0004-refuse-empty-compressed-block.patch`. Test: "a compressed block of size 0 is corrupt at every chunking" in `test-zstd.R`. |
